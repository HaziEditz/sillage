# PROJECT: BUILD A COMPLETE PREMIUM FRAGRANCE RESELLING E-COMMERCE WEBSITE

Act as a senior full-stack developer, software architect, e-commerce specialist, database engineer, security engineer and premium brand UI/UX designer.

Build a complete, production-oriented fragrance reselling website using Replit. The website must be a real, functional application with a persistent database, secure admin dashboard, product catalogue, customer accounts, shopping cart, PayPal checkout, inventory management, order fulfilment and deployment configuration.

This is not a landing-page-only project. Every major button, form, route, database operation and checkout action must work.

The design reference is https://cainternational.co/.

Study the reference website's overall retail structure, navigation, collection browsing, product presentation, bestseller sections, shopping experience and content hierarchy. Adapt those patterns for a premium fragrance retailer. Do not copy its logo, brand identity, exact text, copyrighted imagery or cricket-specific content.

The result should feel like an established fragrance retailer with a distinctive identity, a polished shopping experience and a reliable backend.

# PHASE 1 — INSPECT, PLAN AND ARCHITECT THE APPLICATION

Before writing code:

1. Inspect all existing project files, framework choices, routes, components, dependencies, database configuration and existing functionality.
2. If this is a new project, establish a clean and maintainable full-stack architecture.
3. If the project already exists, preserve working functionality and extend it rather than unnecessarily rebuilding it.
4. Identify the required environment variables, external services, database tables and integrations.
5. Create an implementation plan and work through it in logical stages.
6. Test each important feature before moving on.
7. Keep the application runnable throughout development.

Do not create a frontend that relies on hardcoded arrays of products as its permanent data source. Seed data may be used during development, but production products must come from the database.

Do not claim a feature works until it has been implemented and tested.

# PHASE 7 — PAYPAL PAYMENT INTEGRATION

Use PayPal's official Checkout APIs and supported SDKs.

Reference:
https://developer.paypal.com/checkout/integrate

Implement payment processing through the backend.

## Required behaviour

1. The customer begins checkout.
2. The server validates the cart and reads trusted prices and stock from the database.
3. The server calculates the authoritative order total, including discounts and shipping.
4. The server creates the PayPal order using the appropriate API.
5. The customer approves payment through PayPal.
6. The server captures the approved payment through PayPal.
7. The server verifies the returned transaction information and payment status.
8. Verified payment records are associated with the correct internal order.
9. The order becomes paid only after successful verification.
10. The inventory and fulfilment workflow are updated safely.
11. The customer receives a confirmation email.

## Security requirements

- Use separate sandbox and live configurations.
- Store PayPal credentials in Replit Secrets or secure deployment environment variables.
- Never expose the PayPal client secret to the browser.
- Never commit credentials to version control.
- Never trust a frontend success redirect as proof of payment.
- Verify the payment amount, currency, order reference and capture status.
- Verify webhook signatures using the official PayPal verification mechanism.
- Process webhook events idempotently.
- Handle duplicate notifications and out-of-order events safely.
- Prevent duplicate payment captures and duplicate stock deductions.
- Record relevant payment identifiers and event-processing outcomes.
- Never store raw card details.
- Log payment errors without leaking secrets or sensitive customer data.

Handle successful, pending, failed, cancelled, reversed and refunded payment states appropriately.

Implement refunds through the appropriate PayPal API, with permission checks and persistent refund records.

Do not mark a refund as successful until the result is verified.

Provide documentation for creating a PayPal Developer application, obtaining sandbox credentials, configuring webhooks and switching to live mode.

If credentials have not been supplied, build the integration but clearly report that real payment processing still requires configuration.

Do not simulate successful payments in production.
